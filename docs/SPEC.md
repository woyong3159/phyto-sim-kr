# SPEC — 누적 사양

헌법(CLAUDE.md)이 최상위 문서다. 이 문서는 "실제로 구현된 것"만 누적 기록한다.

## Phase 0 (v0.1.0)

### 폴더 구조
```

src/engine/            순수 엔진(UI·브라우저 의존성 없음)
```

### 엔진 계약
- `state(t+1h) = stepHour(state(t), config, 그 시각의 조치)` — 순수 함수, 입력 상태를 바꾸지 않는다.
- 스텝 내 순서: events → weather → control → greenhouse → rootzone → crop → physiology → protection → labor → market → economy → ledger → time.
- `SimState`는 JSON 직렬화 가능한 순수 데이터. 난수 상태도 그 안에 들어 있어 스냅샷에서 그대로 이어진다.
- 엔진 안에서 `Math.random`, `Date.now`, DOM, IndexedDB 사용 금지(테스트로 강제).

### 세이브(이벤트 소싱)
- 세이브 = `config(seed, 시작일)` + `actions(사용자 조치 로그)` + `hour(마지막 시각)`. 스키마 버전 v1.
- 스냅샷: 게임 시간 7일마다 상태 전체 + 지문 저장.
- 다시 열기: 저장 시각 이하의 가장 최근 스냅샷에서 조치 로그를 재생해 저장 시각까지 복원.
- 저장 시점: 5초 주기(변화가 있을 때), 정지할 때, 화면이 가려질 때(visibilitychange/pagehide).
- 내보내기: gzip JSON(`.physim.gz`), 공유 시트 우선·다운로드 대체. 불러오기는 기존 세이브를 덮어쓰지 않는다.
- 마이그레이션: 읽을 때 `migrateSave`가 버전을 단계별로 끌어올린다. 더 새 버전의 세이브는 지우지 않고 열기를 거부한다.

### IndexedDB 저장소
`saves`, `snapshots`, `ledgerHourly`, `ledgerDaily`, `reports`, `checkpoints`, `kv` (DB v1). 버전을 올릴 때 저장소는 추가만 한다.

### 실행기
- 배속: 정지 / 1일·초 / 7일·초 / 30일·초. 화면 갱신 메시지는 초당 최대 10회.
- 백그라운드 복귀 직후 밀린 시간을 한꺼번에 계산하지 않는다(게임 시간은 화면이 열려 있을 때만 흐른다).

### 화면
- 기준 390×844pt 세로, 안전 영역(safe-area-inset) 반영, 다크 모드, 터치 영역 ≥ 44pt, 호버 의존 없음.
- 타이틀(대시보드 탭): 작물 3종 예고, 엔진 시계 시험, 시스템 점검(엔진·저장소·오프라인·홈 화면 앱).
- 환경 / 근권·양액 / 작물 / IPM: 자리표시 화면(숫자 없음).
- 더보기: 세이브 내보내기·불러오기, 엔진 모듈 현황, 앱 정보.

### PWA
- manifest(standalone, 세로, 아이콘 192/512/maskable + apple-touch-icon 180), 서비스 워커로 전체 파일 사전 저장(precache).
- 업데이트는 자동 교체하지 않고 "새 버전 적용" 배너로 안내.

### 산출물
- 주: `dist/` (PWA) — GitHub Actions가 테스트 후 GitHub Pages에 배포.
- 보조: `dist-single/index.html` (단일 파일, 서비스 워커 없음).

## Phase 1 (v0.2.0) — 시간·지역·기상

### 시간
- 내부 스텝 1시간. 배속: 정지 / 1시간 / 6시간 / 1일 / 7일 / 30일 (실제 1초당).
- 턴 버튼: +1시간, 다음 날(+24시간), 다음 주(+168시간). 최대 속도로 진행하고 멈춘다.
- 자동 일시정지: 켜 둔 종류의 사건이 생기면 그 시각에서 멈추고 시간바 아래에 사유를 띄운다.
  종류: 폭염·한파·장마·태풍·호우·대설·우박(Phase 1부터 발생), 병해충 발견·장비 고장·뉴스·재고 부족(해당 Phase부터).
  설정은 세이브에 저장된다(시뮬레이션 결과에는 영향 없음).
- 작기 시작일은 새 작기 화면에서 사용자가 정한다(1990–2100).

### 지역 (data/regions.json, data/climate.json)
- 기상청 ASOS 29개 지점: 수도권 4, 강원 영서 3, 강원 고랭지 2(대관령·태백), 강원 영동 2, 충청 6, 호남 4, 영남 6, 제주 2. 해안 지점 9곳 포함.
- 월 평년값(1991–2020): 최고·평균·최저기온, 강수량, 강수일수, 상대습도, 일조시간 = SRC / 평균풍속, 일사량 = EST.
- 일사량은 일조시간에서 Ångström–Prescott 식(a=0.25, b=0.50)으로 환산한다.
- 천문 계산(Spencer 1971): 태양 적위, 균시차, 남중 시각(경도 보정), 일출·일몰(−0.833°), 일장, 태양고도, 대기권 밖 일사 Ra(FAO-56).

### 기상 생성기 (src/engine/weather)
1. **일별 기준선**: 월 평년값을 주기 3차 에르미트 스플라인으로 보간. 일별 값의 월평균이 평년값과 같아지도록 마디를 반복 보정(평균 보존).
2. **일평균기온**: 기준선 + 빠른 AR(1)(φ=0.65) + 느린 AR(1)(φ=0.90, 분산 12%) + 비 오는 날 보정.
   σ는 월별(내륙 1.8–3.6°C) × 기후형 배율(해안 0.85, 고랭지 1.05, 제주 0.75).
3. **강수 발생**: 2상태 마르코프. P(wet|dry) = π(1−r), P(wet|wet) = r + π(1−r). π = 평년 강수일 비율, r = 0.25(장마 중 0.45).
4. **강수량**: Weibull(k=0.75), 평균 = 평년 강수량 ÷ 강수일수.
5. **비 오는 날 효과**: 일사 ×0.4, 습도 +10%p, 일교차 ×0.65, 기온 보정(여름 −1.5°C … 겨울 +0.8°C).
   맑은 날은 반대 방향으로 자동 보정되어 월평균이 평년값으로 유지된다. 일사는 청천 상한(0.75·Ra)을 넘지 않는다.
6. **시간 분해**
   - 기온: Parton & Logan(1981) — 낮 사인, 밤 지수 감쇠(a=1.86, b=2.20, c=−0.17).
     수정 2가지: ① 밤 끝에 최저기온에 정확히 닿도록 감쇠항 정규화, ② 형상 지수 γ(날짜별)로 일평균을 평년 평균기온에 맞춤.
   - 일사: 태양고도 사인값 비례(10분 간격 적분).
   - 습도: 하루 동안 수증기압(이슬점) 일정. 24시간 평균 습도가 그날 일평균 습도와 같아지는 수증기압을 찾는다.
   - 바람: 일평균 × (1 + 0.35·cos) — 오후 2시 최대. 강수: 연속된 시간대에 균등 배분.
7. **극한 기상**
   - 폭염(일최고 ≥33°C 2일 연속 = 주의보 수준, ≥35°C = 경보 수준), 한파(일최저 ≤−12°C / ≤−15°C 2일 연속): 생성된 계열에서 판정.
   - 장마: 해마다 시작·종료일을 평년일 ± 6일(표준편차)로 정하고, 기간 중 강수 연속성을 높인다.
   - 태풍: 월별 영향 태풍 수(6월 0.3, 7월 1.0, 8월 1.2, 9월 0.8, 10월 0.1) × 지점 가중치. 2일간 비·강풍. 평년 강수에서 태풍 몫을 미리 빼 둔다.
   - 대설: 일평균기온으로 눈/비 판정, 신적설 = 강수량 × 1 cm/mm. 5 cm 주의보, 20 cm 경보 수준.
   - 호우: 일강수량 ≥110 mm. 우박: 기후형별 연 0.4–1.2일.
8. **출력**: 시간별 기온·습도·일사(MJ/m², W/m²)·풍속·강수·태양고도 / 일별 최고·최저·평균기온, 습도, 일사, 강수, 풍속, 최대순간풍속, 신적설, 장마·태풍·우박 표시.

### 결정론

- 엔진 코드에서 Math.exp 등과 `**` 사용을 테스트로 금지.
- seed: 새 작기마다 자동 생성, 직접 입력 가능. 같은 지역·시작일·seed → 같은 날씨.

## Phase 2 (v0.3.0) — 시설·미기상·환경 제어

### 시설·장비 (data/facilities.json, equipment.json)
- 시설 4종: 단동 비닐, 연동 비닐, 연동 PO필름, 벤로형 유리. 각각 투과율, 열관류율, 피복 면적비, 측고·평균 높이, 틈새 환기, 측창·천창 면적, 적설·풍속 한계, 노후 감광, 시공비.
- 구성 항목: 면적, 피복 겹수(1중/2중), 피복 경과 연수, 보온커튼(0–3겹 × PE·부직포·알루미늄·다겹), 차광막(35/55/75%), 측창·천창, 방충망(1.0/0.6/0.4 mm), 순환팬, 포그, 제습기,
  난방기(온풍기 + 연료 4종 / 전기 / 공기열 히트펌프 / 지열)와 용량, 냉방(패드앤팬 / 히트펌프), CO2(액화탄산 / 연소식), 보광(LED / HPS)과 광량, 양액 냉각기·가온기, 시험용 군락 LAI.
- 장비마다 설치비, 내용연수, 평균 고장 간격(MTBF), 수리 시간, 소비전력·효율.
- 구성은 작기 시작 때 정하고 작기 중에도 바꿀 수 있다(조치 `gh/setup`). 설치비 견적은 `installCost()`.

### 미기상 모델 (src/engine/greenhouse/model.ts) — single-zone, 10분 × 6
- 상태: 실내 기온, 수증기압, CO2, 축열체(바닥·토양 표층) 온도, 양액 온도, 창·커튼·차광 위치, 먼지, 지붕 적설.
- **에너지**: 공기 절점 + 축열체 절점. 일사는 군락(1 − e^(−k·LAI))과 바닥이 나눠 흡수한다.
  군락은 Penman–Monteith로 증산 잠열과 현열을 가른다(기공저항: 광·고온·VPD·CO2 항). 바닥이 받은 일사의 절반은 곧바로 공기로, 절반은 축열.
  손실: 피복(U값 × 피복 면적비, 커튼은 열저항 직렬), 환기·틈새, 패드앤팬, 심층 토양.
- **피복면 열수지**: 실내 현열 + 결로 잠열 = 외부 방열을 풀어 피복면 온도를 구한다. 결로가 생기면 피복이 데워져 결로와 현열 손실이 스스로 줄어든다.
- **환기량**: 풍압(Cd·A/2·√Cw·u)과 부력(굴뚝 효과)의 제곱합 제곱근 + 틈새. 방충망은 유량 배율. 측창과 천창을 함께 쓰면 굴뚝 높이가 커진다.
- **수분**: 증산 + 포그 + 연소 수증기 − 환기 − 피복 결로 − 제습. 포화를 넘으면 물방울로 맺히고 잠열은 공기로 돌아온다. 커튼 소재별 투습도.
- **CO2**: 공급 − 순흡수(시험용 군락 광합성 − 호흡) − 환기. 공급기는 목표에 필요한 만큼만(용량 한도) 넣는다.
- **광**: 투과율 × 2중 피복 × 노후 × 먼지 × 지붕 눈 × 차광 × 닫힌 커튼 → PPFD(+ 보광). DLI 누적.
- **결로·엽면 습윤**: 피복면 온도 < 이슬점이면 결로, 엽온 < 이슬점이면 엽면 습윤. 시간 단위로 누적(Phase 6 입력).
- **엽온**: 군락 에너지 균형(흡수 복사 − 장파 손실 − 증산 잠열 = 현열).
- **수치 해법**: 공기·수분·CO2는 서브스텝마다 지수 해(정확해). 에너지·물·CO2 장부를 스텝 평균값으로 적분해 수지가 반올림 오차 수준으로 닫힌다.
- **구조**: 지붕 적설(강설 − 외기·실내 열에 의한 융설 − 흘러내림)이 한계를 넘으면 붕괴, 순간풍속이 한계를 넘으면 피복 파손(틈새 급증). 되돌려지지 않는다.
- **고장**: 가동 중인 장치가 시간당 1/MTBF 확률로 고장('failure' 난수 흐름). 수리를 맡기면 정해진 시간 뒤 복구.

### 제어 (사용자 설정, 조치 `gh/control`)
- 난방: 주간·야간·일출 전 설정온도 + 시간대별 프로그램(최대 6개). 온풍기는 ±0.5°C 히스테리시스, 히트펌프는 비례 제어.
- 환기: 개시 온도, 비례대, 단계 개도, 최대 개도, 10분에 25%p 이동 제한, 강풍·강우 닫힘.
- 습도: 상한(제습기 또는 환기 우선), 습도 환기 최대 개도, 하한·온도 조건 포그.
- CO2: 목표, 시간대, 창 개도 한계. 차광: 외부 일사 임계값(히스테리시스 50 W/m²). 커튼: 일몰·일출 기준 시각 + 외기온 조건.
- 보광: 시간대 점등 / 일장 연장(전조) + 외부 일사 소등 + 목표 DLI. 냉방 개시 온도. 양액 온도 범위.

### 비용 (data/prices.json)
- 시간별 연료(L)·전력(kWh)·CO2(kg) → 원. 전력 = (전력량요금 + 기후환경·연료비조정) × 부가세·기금 + 계약전력 기본요금(일할).
- 오늘·어제·작기 누적으로 쌓고 일 단위 원장에 남긴다(Phase 7 장부 입력).

### 화면
- 새 작기: 3단계에 시설·장비 선택(시설 카드, 설치비 견적).
- 환경 탭 4분할: 현황(내부 vs 외부 표, 오늘 에너지 비용, 장비 상태·수리, 48시간 그래프 5종) / 제어(설정 편집 → 확인 → 적용) / 시설·장비(변경, 피복 세척) / 외기 30일(실내 최저, 일별 에너지 비용 포함).
- 대시보드: 온실 안 카드. 자동 일시정지에 "시설 붕괴·파손", "장비 고장" 추가.

### 저장
- 세이브 스키마 v3(시설·장비·제어 설정), 엔진 상태 v3. 시간 단위 원장을 최근 14일 보존.

## Phase 3a (v0.4.0) — 작물 생육 코어 + 오이

Phase 3은 3a(코어 + 오이) / 3b(딸기) / 3c(와사비)로 나눠 진행한다.

### 구조 (src/engine/crop/)
- `canopy.ts` 군락 광합성, `cucumber.ts` 오이 모듈, `index.ts` crop 모듈(조치 처리·온실 연결), `types.ts`.
- 단위: 마디·잎·과실은 "평균 한 포기" 기준, 저장고·수량·건물 흐름은 온실 바닥 1 m² 기준. 생리일수(pd) = 최적온도에서의 하루.
- **온실과의 연결**: 온실 모델이 10분마다 `canopyPhoto()`로 총광합성을, 유지호흡을 계산해 CO2 수지에 넣고, 그 합계(gh.out.cGross·cMaint)를 작물 모듈이 그대로 받는다.
  → 온실 공기의 CO2 수지와 작물의 탄소 수지가 같은 숫자를 쓴다. 생장호흡은 한 시간 뒤에 공기로 나간다.
  증산(Penman–Monteith)은 작물의 LAI·흡광계수·기공저항 최솟값을 쓴다.
- 근권 인터페이스(Phase 4): `rootzoneSupply()`가 수분 가용도와 양분 스트레스를 돌려준다. 지금은 둘 다 1.

### 코어
- **잎 광합성**: 비직각쌍곡선. Pmax = 품종 × 엽령 곡선 × (잎 두께)^0.5 × f(엽온: 사다리꼴) × f(Ci) × 되먹임. 초기기울기 = 양자수율 × (Ci−Γ*)/(Ci+2Γ*).
  Ci/Ca = 1 − (1 − Γ*÷Ca)(0.14 + 0.116·VPD): 공기가 건조하면 기공이 닫혀 광합성이 준다. Γ*는 온도에 따라 증가(고온 광호흡).
- **군락**: Goudriaan 3점 가우스 적분(깊이) × 양지엽·음지엽, 양지엽은 잎 각도 3점 적분. 직달광·산란광을 따로 감쇠.
  산란광 비율 = 대기 투과율 관계식(Spitters) + 피복재 헤이즈. 깊이별로 그 자리 잎의 엽령·두께를 쓴다(아래 잎일수록 늙음).
  흡광계수 k = 0.8 − 0.05·LAI(하한 0.6), 유인 방치 시 잎 뭉침으로 감소.
- **호흡**: 유지호흡 Σ m_i·W_i·Q10^((T−25)/10) — 저장 당이 없으면 그만큼 못 하고 "기아" 스트레스(늙은 잎 소모). 생장호흡은 기관별 전환효율과 탄소 비율에서 계산.
- **저장고와 분배**: 광합성 산물 → 저장고 → 시간당 10%까지 꺼내 씀. 기관별 잠재 생장(sink strength)에 비례해 분배(G5).
  저장고가 잎 건물의 25%를 넘으면 광합성 되먹임 억제.
- **엽면적**: 생리일수에 따른 엽 출현, 잎마다 로지스틱 확장. SLA = f(최근 DLI, 평균기온). 당이 모자라면 잎이 얇아지며(SLA 상한까지) 면적을 유지.
  노화: 수명(50 pd) 초과, 그늘(군락 위 광의 4% 미만), 기아, 저온·고온·동해.
- **스트레스(G3)**: 과정별(광합성·엽 확장·과실 비대·착과) = 요인별 계수의 곱. 반응곡선은 JSON의 사다리꼴. 원장에 전부 기록.
  수분 민감도 순서: 엽 확장 → 과실 비대 → 광합성.
- **발육(G4)**: 베타 함수(오이 Tbase 10 / Topt 28 / Tmax 40).

### 오이
- 마디: 0.75매/pd. 마디마다 잎 1 + 암꽃(비율 = 품종값 − 0.03/°C·야온 − 0.05/h·일장, 10일 이동평균) + 곁순 눈.
- 과실: 마디 출현 10 pd 뒤 개화(단위결과). 잠재 생장 = Gompertz(개화 후 pd). 개화 전 3 pd–개화 후 6 pd 사이에 착과 계수(공급/수요 × 온도)에 따라 퇴화.
- 절간장 = f(야온, DLI) → 도장 지수. 곁순: 10 pd 뒤 신장(당 부족이면 억제), 방치하면 가지당 6마디까지.
- 수확 등급: 상품 / 중품(약한 곡과, 과대과) / 비상품(심한 곡과, 초과대, 노화과). 곡과율 = f(비대기 평균 당 부족도, 유인 방치, 품종).
- 장해: 5°C 미만 저온(엽면적 손실), 0°C 이하 동해(개체 고사), 엽온 42°C 초과 엽소. 잎이 모두 없어지면 고사.
- 작형: 촉성·반촉성·억제(안내용). 재식밀도와 정식일은 사용자가 정한다.

### 작업과 조치
- 조치: `crop/plant`(정식), `crop/plan`(작업 계획), `crop/work`(즉시 작업: train·deleaf·harvest·pinch·thin), `crop/remove`(철거). 새 작기 설정의 `crop: {day, order}`는 예약 정식.
- 작업 계획: 유인 간격·곁순 남길 마디·적화 마디·적과 상한·적심 마디, 적엽 간격·남길 잎 수, 수확 간격·기준 무게. 간격 0 = 방치.
- 작업마다 노동 시간(h/10a × 면적)이 쌓인다.

### 품종 (data/varieties.json)
청춘 백다다기, 입추백다다기, 겨우살이청장(취청형), 가시계 A(가상). 암꽃 비율, 광합성·잎 크기·과실 크기 배수, 수확 무게, 과형, 곡과 민감도, 내저온·내고온, 병 저항성(Phase 6), 가격 프리미엄·묘 가격(Phase 7).

### 화면
- 작물 탭: 현황(2D 작물 그림, LAI·마디·과실, 생육 상태, 건물 분배, 스트레스 14종, 수확) / 작업(계획 + 즉시 실행 + 노동 시간 + 철거) / 생육 그래프(작기 전체 일 단위 7종).
- 새 작기: 4. 작물·정식(품종 카드, 작형, 재식밀도, 정식일). 끄면 빈 온실.

## Phase 3b (v0.5.0) — 딸기

### 구조
- `crop/strawberry.ts` 추가, `crop/index.ts`가 작물별로 분기한다. 군락 요약(`buildCanopy`)·스트레스·분배·잎 로직은 오이와 같은 코어를 쓴다.
- 상태: 공통 CropState + 딸기 전용 `sb`(저온 누적, 휴면, 화아분화 진행, 화방·관부 수, 일장, 런너, 봉군 세력, 첫 개화) + `quality`(수확 품질 가중합).
- 과실 무리(Fruit)에 화방 번호(node)·차수(rank)·수분 적산(poll)·비대기 기온 적산(tSum).

### 화아분화 (`inductionRate`)
- 하루 진행량 = f_T(일평균) × f_P(일장, 온도) × f_N(질소) ÷ 20일. f_P: 15°C 이하 1, 20°C 이상은 단일 반응(한계 일장 13.5 h + 품종차, 폭 1.5 h), 그 사이는 선형 혼합.
- 일장은 자연 일장 + 야간 보광등 가동 시간(전조)이다 → 전조는 휴면을 막지만 15°C 이상에서는 화아분화도 늦춘다.
- 진행이 1이 되고 직전 화방 뒤로 관부당 잎 4매가 나왔으면 화방 분화. 분화 후 36 pd에 1번화 개화, 차수마다 3.5 pd 뒤.
- 정식 시점: 야냉 단일처리 묘 = 분화 완료. 그 밖에는 직전 40일의 평년 기온(+1°C)·일장으로 진행량 계산(구입묘 질소 0.75, 자가묘는 사용자 질소 수준).

### 화방·과실
- 차수별 꽃 수 1·2·4·8(품종 화방당 꽃 수까지), 적화로 화방당 남길 수 지정. 과실 잠재 크기 = 품종 1번과 × 차수 배수(1, 0.72, 0.5, 0.36) × 수정 배수.
- 개화 후 26 pd에 성숙(20°C 약 28일, 12°C 약 50일). 2.5 pd 넘기면 과숙. 3번화 이상은 동화산물 부족 시 퇴화. −0.5°C 아래에서 꽃 동해.
- 관부: 화방이 분화할 때마다 +0.4개(남길 관부 수까지). 관부 수만큼 엽 출현과 화방당 꽃이 늘어난다.

### 수분
- 시간별 수분 진행 = (벌 활동 × 벌 종류별 속도 + 자가 수분) × 꽃가루 활력. 벌 활동 = f(실내기온) × f(PPFD) × 봉군 세력, 꽃가루 활력 = f(기온, 품종) × f(습도).
- 개화 후 3 pd 동안 적산 → 수정률 = 1 − e^(−Σ) → 과실 잠재 크기 배수(0.35–1)와 기형과 비율(1 − 수정률).
- 봉군 세력은 매일 감소(꿀벌 0.8%/일, 뒤영벌 2%/일). 벌통 교체 작업으로 100% 복귀.

### 휴면·런너
- 휴면 정도(0–1): 단일(13.5 h 미만)·저온(17°C 미만)에서 깊어지고 그 밖에는 풀린다. 0–7°C 누적 시간이 품종 요구량을 넘으면 빠르게 해제.
  효과: 새 잎 크기 −55%, 엽 출현 −50%(완전 휴면 기준).
- 런너: 장일(12.5 h 초과)·고온(12°C 초과)에서 발생, 제거 전까지 동화산물을 가져간다.

### 품질
- 과실 건물률 = 품종값 × (1 + 0.25 × (비대기 공급비 − 0.8)) × (1 − 0.012 × (비대기 평균기온 − 12)) × (1 + 0.12 × log2(DLI ÷ 10)).
- 당도 = 1.15 × 건물률(%) − 0.5. 산도·경도 = 품종값 × 기온 반응. 등급: 상품(15 g 이상 정상과) / 중품 / 비상품(8 g 미만, 심한 기형, 과숙).

### 작업·조치
- 작업 계획 추가 항목: 수정벌 종류와 교체 간격, 화방당 남길 꽃 수, 남길 관부 수, 런너 제거 간격, 질소 수준(임시).
- 즉시 작업 추가: `runner`, `bees`. 정식 주문에 묘 종류(buy/own)와 야냉 처리.
