## 로드맵 (Phase 1–9)

순서 원칙: 작물 모델(가중치 0.45)이 가장 중요하지만, 작물은 "온실 안 환경"을 입력으로 받는다.
그래서 환경을 먼저 최소 충실도로 세우고(Phase 1), 곧바로 작물에 가장 많은 Phase를 쓴다(2–3, 5).
인과 원장(ledger)은 Phase 1부터 뼈대를 깔아 모든 Phase가 기록을 남기게 하고, 분석 기능은 Phase 8에서 완성한다.

### Phase 1 — 기상·온실 미기상·환경 제어
- weather: 지역 평년값(기상청 1991–2020) + seed 고정 확률 편차. 시간별 기온·일사·습도·풍속.
- greenhouse: 에너지·수분·CO2·광 수지. 피복재 투과율, 환기, 난방, 차광·보온 스크린, 보광, CO2 시비.
- control: 설정값(setpoint), 히스테리시스·비례 제어. 필요 시 10분 서브스텝.
- ledger 뼈대: 시간별 상태 기록, 최근 14일 시간 단위 + 작기 전체 일 단위 보존.
- 결정론 보강: 엔진 전용 수학 함수(exp/log/pow 등)를 자체 구현해 기기 간 비트 일치 확보(KNOWN_LIMITS L2).
- UI: 환경 탭(현재값, 24시간·14일 차트, 설정값 입력).
- 검증 시나리오 예: 한겨울 무가온 → 야간 실내온도가 외기 근처까지 하강 / 환기 닫고 맑은 날 → 과열 / 보온 스크린 유무에 따른 난방 부하 차이.

### Phase 2 — 작물 생육 코어 + 오이
- crop 코어: G1(건물 생산), G2(광 흡수, Gaussian 3점 적분), G3(스트레스 합성), G4(열시간 발육), G5(sink strength 분배).
- 오이 모듈: 마디 전개, 착과·유과 고사(abortion), 과실별 생장(Marcelis식 분배), 적엽·유인·적과 조치.
- 오이를 먼저 하는 이유: 생육이 빠르고 건물분배 모델 문헌이 가장 탄탄해서 코어 검증에 유리하다.
- UI: 작물 탭(LAI, 기관별 건물중, 착과 현황, 스트레스 원인).
- V4 벤치마크 1차: 농산물소득자료집 시설오이 10a당 수량과 비교.

### Phase 3 — 딸기(3a)·와사비(3b)
- 3a 딸기: 화아분화(저온·단일), 휴면·저온 요구도, 화방(truss)별 착과·과실 비대, 런너, 당도 형성. 고설 수경 기준.
- 3b 와사비: 저온성·내음성, 고온 장해, 근경(rhizome) 비대, 긴 재배 기간. 문헌이 적어 EST 비중이 높을 것 — 근거를 특히 꼼꼼히 기록.

### Phase 4 — 근권·양액
- 배지(코이어·암면·펄라이트 등) 수분 특성, 급액·배액, 근권 EC/pH 동태, 이온별 흡수(N, P, K, Ca, Mg, S + 미량요소).
- G6 염해(Maas–Hoffman, 기질 EC 환산), 원수 성분, 양액 처방(mmol/L), 순환식/비순환식.
- 물·양분 질량 보존 검증(오차 < 1%).
- UI: 근권·양액 탭.

### Phase 5 — 생리장해·PGR·작업과 노동
- physiology: 칼슘 결핍(팁번·배꼽썩음), 기형과, 곡과, 열과, 고온·저온 장해, 생장조절제 반응.
- labor: 적엽·적과·유인·수확·스카우팅의 노동 시간과 인력 제약.

### Phase 6 — 병해충·방역 + 관측 모드
- G7 병 감염 위험(온도·습윤시간·습도), 잠복기, 포자 형성.
- G8 해충·천적 동태(온도 의존 증식, Holling II 포식), 농약 효과·잔효·저항성 발달, 천적 영향.
- G9 외부 유입과 방역 조치.
- 관측 모드(학습/현실): 스카우팅 탐지 확률, 실험실 분석 3일 지연, 잠복 감염 비가시.
- UI: IPM 탭.

### Phase 7 — 경제·시장·이벤트
- economy: 토지(국내 지역), 시설·장비 CAPEX, 감가상각, OPEX(난방·전기·양액·인건비), 금융.
- market: 가격 변동, 등급, 판매 채널과 수수료. G10 손익.
- events: 뉴스·재해·시장 충격(seed 고정).
- UI: 장부.

### Phase 8 — 리포트·반사실 분석·A/B 실험
- 작기 리포트(확정 저장), 인과 원장 기반 "수량 손실 원인 분해".
- 반사실 분석(조치 하나를 바꿔 재계산), 작기 비교, 다중 seed A/B 실험.
- 워커 청크 계산 + IndexedDB 체크포인트 이어하기 + Screen Wake Lock + 해상도 옵션(빠름/정밀).

### Phase 9 — 통합 검증과 마감
- V4 벤치마크 전 작목(수량 ±25%, 경영비 ±30%), 필요한 보정은 CAL 태그로 기록.
- 아이폰 성능 예산 점검(30일/초), 접근성·다크 모드 마감, 단일 파일 빌드 마감.
- KNOWN_LIMITS 정리, 전체 RFS 재산정.

## 결정 기록 (사용자 대신 내린 기술 결정)
- 하단 탭 6개: 대시보드 / 환경 / 근권·양액 / 작물 / IPM / 더보기(장부·리포트·세이브). 390pt 폭에서 탭 하나가 65pt로 넉넉하다.
- 배포 경로는 상대 경로(base './')로 빌드 → GitHub Pages·Cloudflare Pages·Netlify 어디든 수정 없이 올라간다.
- 엔진 워커는 앱 파일 안에 포함(inline) → PWA와 단일 파일 빌드가 같은 코드 경로를 쓴다.
- 난수: sfc32(정수 연산만) + 영역별 독립 흐름(weather / pestIntro / market / events).
- 시작일·seed는 세이브를 만들 때 한 번 정해지고 이후 고정.
